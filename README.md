# 移动端培训部聚合平台

面向培训部的移动端 H5 聚合平台。当前已上线两个入口：**查询招生简章**（班级名称查询 / 教室查询 / 年级查询 / 功能查询 / 空教室查询 / 晚课查询）与 **数据统计**（春季 / 暑期 / 秋季招生简章，按校区统计与三学期对比），其余两个入口为占位。查询页 6 个入口按钮自动换行（每行 3 个），不做横向拉动。

- 国内备用链接：https://training-portal-64035.app.workbuddy.host/?sharecode=D7B7JKPWDA （零子资源单文件版；转发须保留完整 `?sharecode=`）
- 单文件离线版：`E:\桌面\移动端聚合平台\移动端培训部聚合平台_单文件离线版.html`，微信传文件到手机后用浏览器打开，完全不走链接、离线可用

## 页面结构

```
首页（功能入口宫格）
  ├─ 查询招生简章
  │    ├─ 导入页：导入 招生简章.xls + 教室功能.xlsx
  │    └─ 查询页：班级名称查询 / 教室查询 / 年级查询 / 功能查询 / 空教室查询 / 晚课查询（双校区切换）
  └─ 数据统计
       ├─ 导入页：分别导入 春季 / 暑期 / 秋季 招生简章（1~3 份）
       └─ 统计页：校区切换（全部 / 厦港 / 镇海）+ 学期切换 + 三学期对比 + 导出 .xlsx
```

## 功能说明

| 功能 | 说明 |
|---|---|
| 班级名称查询 | 搜索招生简章「班级名称」列：输入名称中的任意字符即模糊命中（如 `舞蹈` → `少儿舞蹈` 类班级；`舞提` 这类不连续字符按原顺序出现也命中，单字亦可，英文忽略大小写），匹配字符在结果里高亮；结果按「星期 → 开始时间」排序，表格列含 班级名称 / 教室 / 上课时间 / 教师 / 剩余名额 / 学费；按当前校区过滤，另一校区有匹配时给出提示 |
| 教室查询 | 输入教室号模糊匹配（如 `409`），查看该教室功能标签与全部排课班级；表格按「星期 → 开始时间」排序，列含 班级名称 / 上课时间 / 教师 / 剩余名额 / 学费 |
| 年级查询 | 读取招生简章「招生对象-年级」列。该列是范围文本（如 `小学一年级~小学六年级(初中预备班)`），按有序年级序列自动展开成覆盖到的每个年级，因此下拉选中「二年级」即可命中所有覆盖该年级的班级。下拉按学段分组（幼儿 / 小学 / 初中 / 高中 / 其他），显示「一年级、二年级…」；结果表格列含 班级名称 / 招生年级 / 教室 / 上课时间 / 教师 / 剩余名额 / 学费，按上课时间排序、按当前校区过滤，进入面板和切换校区时自动刷新 |
| 功能查询 | 从教室功能表汇总全部功能词生成下拉（按拼音排序）；结果按教室**折叠**成表格（教室 / 功能 / 班级数 / 详情），功能列优先显示所选功能，点击教室行展开该教室全部班级（班级名称 / 上课时间 / 教师 / 剩余名额 / 学费，按「星期 → 开始时间」排序）及完整功能 |
| 空教室查询 | **点星期按钮即自动刷新列表**（与晚课查询一致，无需再点查询按钮），进入面板、切换校区时也会自动刷新；按星期输出矩阵表：行为教室（含功能），列为时段；周末 6 节（上午 2、下午 2、晚上 2），周一至周五仅晚上 2 节；「空」=空闲，「—」=已排课；**按教室号升序**（纯数字编号按数值排，`307-2` 紧跟 `307`；特殊场地按名称排在数字教室之后） |
| 晚课查询 | 周一至周日按钮，点击即展示该天**晚上 2 节**（晚1 17:20-18:50、晚2 19:00-20:30）有课的教室；折叠表格列出教室、功能、晚1/晚2 占用、晚课班级数，点击教室行展开当晚班级明细（班级名称 / 上课时间 / 教师 / 剩余名额 / 学费） |

双校区：厦港 / 镇海，可一键切换。

- **已满标记**：班级名称查询、教室查询、年级查询的结果表，以及功能查询、晚课查询展开后的班级明细中，剩余名额为 0（页面显示「已满」）的班级整行标为橙色 `#FFC000`。负责渲染班级明细的 `clsTable()` 统一处理，因此五个带剩余名额列的查询口径一致；空教室查询是时段矩阵、没有剩余名额列，不标色。

## 数据统计（第二个入口）

- **导入**：分别导入春季 / 暑期 / 秋季招生简章，格式相同、内容不同；只导入一份即可统计，三份齐全才显示「三学期对比」。解析结果缓存到 `localStorage`（键 `agg_stat_v1`），与查询入口的数据相互独立；页面启动时按当前分类口径重算缓存中的班级类别，规则更新后无需重新导入。
- **校区**：取招生简章「区域」字段（`【厦港校区】报名入口` / `【镇海校区】报名入口`），映射为 厦港 / 镇海；结果页提供「全部校区 / 厦港 / 镇海」切换。
- **统计项**：班级数量、专业出现次数、教室出现次数、教师出现次数、已招人数（总和 + 按专业 + 按班级分类）、学费合计、书杂费合计、总收入（各为总和 + 按专业）、幼儿班 / 少儿班 / 青年班 / 跨年级段的班级数与已招人数。
- **结果页折叠**：「按专业统计」「教室出现次数」「教师出现次数」三张表**默认折叠**，标题条显示条目数，点击展开 / 收起；展开状态在切换校区、学期时保持。概览卡片、班级分类始终直出，三学期对比表不折叠。
- **班级分类明细**：分类卡片同时显示班级数与已招人数；**点击某个分类**即在其下方展开该分类的全部班级（班级名称 / 校区 / 专业 / 招生年级 / 教室 / 教师 / 已招人数 / 学费单价 / 总计单价），再点一次收起。明细随校区、学期切换自动刷新，表格可上下、左右滑动。
- **金额口径**：一个班级的学费 = `已招学员 × 学费`，书杂费 = `已招学员 × 书杂费`，收入 = `已招学员 × 总计`；合计为所有班级求和，按专业区分同理。简章里「总计 = 学费 + 书杂费」，因此 总收入 = 学费合计 + 书杂费合计（回归测试已验证）。
- **班级分类**：按「招生对象-年级」范围的两个端点同时判断，**范围须完整落在同一学段内**：起始 ≥ 幼儿且结束 ≤ 幼儿大班 → 幼儿班；起始 ≥ 小学一年级且结束 ≤ 高中三年级 → 少儿班；起始 ≥ 成人且结束 ≤ 成人 → 青年班；其余 → 跨年级段。因此跨学段范围（如 `幼儿大班~小学六年级(初中预备班)`、`幼儿~成人`、`小学三年级~成人`）一律归跨年级段。四类单独计数，合计恒等于班级总数。
- **多值字段**：教室字段内换行表示一个班占多间教室，拆分后分别计次；专业名本身含顿号（如「体能训练、跳绳」）不拆分；教师按原值统计。
- **对比**：三份简章都有时显示，共 16 项指标（含四类班级的班级数与已招人数），差值 = 秋季 − 春季，增幅 = 差值 ÷ 春季；切换校区后同步刷新。
- **导出**：用 `XLSX.writeFile` 生成 `.xlsx`。单学期导出 7 个 sheet（概览 / 按专业统计 / 专业出现次数 / 教室出现次数 / 教师出现次数 / 班级分类 / 班级分类明细），三份齐全时附加「三学期对比」sheet 共 8 个；「班级分类」sheet 含班级数与已招人数，「班级分类明细」逐班列出类别与各项信息；概览与对比也包含各分类的已招人数。对比页导出只含对比 sheet。

## 微信内置浏览器兼容

服务端在 iOS 微信 / Android X5 / 旧 TBS 三种 UA 下均返回 200、无跳转、无 CSP 阻断；页面业务代码与本地一致。为覆盖**旧版微信 X5/TBS 内核**（Chrome 66 ~ 73）做了三项改造：

- **语法降到 ES2018**：移除 `??`、`String.matchAll`（改用 `weekDaysIn()` 用 `match` 提取星期）、`Array.flatMap`（改用循环）、`Object.fromEntries`（改为显式初始化对象），以及旧内核不支持的 CSS `inset`。用 `acorn` 以 `ecmaVersion: 2018` 解析全部内联脚本验证通过。
- **零外链加载**：解析库 `onerror` 从 `cdn.jsdelivr.net` 改为同域重试（`xlsxRetry`），最多 2 次；导入页另有手动重试按钮（`xlsxReload`）。单文件离线版直接内嵌解析库，连这个请求都不发。
- **导出引导**：微信内点「导出统计结果 .xlsx」先弹出提示层——iOS WKWebView 不支持 `<a download>` + Blob URL 下载，引导用户点右上角「···」→「在浏览器打开」后再导出；另提供「仍然尝试导出」按钮，确认后本次会话不再重复弹窗。非微信环境保持直接下载。

仍需说明的限制（**非代码可修复**）：`netlify.app` 不在微信白名单域名内，首次打开必有「将要访问」外链确认页，点「继续访问」即可；彻底去掉需已备案域名 + 认证服务号配置微信业务域名。iOS 微信选 `.xls` 文件需经「浏览 → 文件 App」。推荐用国内备用链接或单文件离线版。

## 数据说明

- **不内置任何数据**。用户须在导入页选择两份文件，文件在**浏览器本地**由 SheetJS 解析，不上传服务器。
- **SheetJS 解析库 `xlsx.full.min.js` 随站点一起发布**（与 `index.html` 同目录），页面**零外部 CDN 依赖**，微信内置浏览器 / 弱网下也能正常导入，且浏览器会缓存。脚本用 `defer` 延迟加载，页面先渲染、不会出现长时间白屏。加载失败时只在本站**同域重试**（最多 2 次，带 `?retry=` 参数），不再回退到任何外部 CDN；仍失败会在导入/统计导入页显示「重试加载解析库」按钮，可手动同域重试。
- 解析结果缓存在浏览器 `localStorage`，下次打开直接生效；可在导入页底部一键清除并重新导入。
- **学费列取自招生简章的「总计」列**（= 学费 + 书杂费，含教材杂费的实际缴费总额），显示为 `¥1,000` 形式；该列为空时显示 `—`。招生简章另有「学费」「书杂费」两列，页面按需求使用「总计」。
- **班级名称查询**只读取招生简章的「班级名称」列，与教室功能表无关；匹配的是班级全名（如「【镇海】少儿舞蹈班(提高) C302」，用户口中的「少儿舞蹈提高」是简称）。匹配规则为「输入的字符按原顺序都出现在名称中」，所以连续子串、间隔字符、单个字都支持；命中字符会高亮，且对结果做了 HTML 转义，班级名含特殊字符也不会破坏页面。
- **年级查询**读取招生简章「招生对象-年级」列（当前 505 个班共 62 种范围取值，如 `幼儿大班~小学三年级`、`小学二年级~初中三年级`、`成人~成人`）。按 `GRADE_ORDER` 的学段顺序把 `A~B` 展开成覆盖到的每个年级；端点带 `(初中预备班)` 等括号后缀、或简写成「小学六年级」都能识别；「幼儿」是泛称，只作范围起点、不作为下拉选项。展开在运行时由年级文本推导，不额外占缓存。**若浏览器里是旧版本导入的缓存（不含 `grade` 字段），年级查询会提示回导入页清除数据并重新导入两份文件。**
- **功能关联**：以「校区 + 教室名」为键，把教室功能表的功能挂到招生简章的教室上。两表教室名走同一套规范化（剥离 `厦港教室` / `镇海教室` / `厦港` 前缀、去掉前导空格等），因此功能表的「厦港教室301」「 思明小学小操场」「镇海二楼大礼堂」都能与简章对应，不会重复统计。两个校区存在 301/302/401/402/403 等重名教室，故关联必须带校区条件。
- **功能表解析**：校区标题只识别 `厦港教室` / `镇海教室` / `镇海教室20间` 这类标题格（避免把带前缀的教室名误判成表头）；功能列按空白字符（含全角空格）、顿号、中英文逗号、分号、斜杠拆分，兼容新旧两版表格。
- 若教室功能表某校区的功能列未填写，该校区教室显示「未登记」，结果页会提示未登记数量，功能查询下拉也会给出说明。
- **晚课判定**：课程时间与晚1/晚2 任一节次重叠即计入晚课（跨节长班会同时占两节）；结果直接由班级的「上课时间」文本推导，不依赖课次缓存，因此旧版本导入过的数据也无需重新导入即可使用晚课查询。功能信息则取自导入时的教室功能表，更新过功能表需重新导入。
- **页面解析逻辑全部在 `index.html` 的内联脚本里**。`build_data.py` 是早期离线统计脚本，其中的教室功能列表为旧版快照、不参与页面运行；页面数据一律以导入的两份 Excel 为准。**功能表内容更新后，需在导入页点「清除已导入的数据，重新导入」才会生效**（浏览器缓存的是导入时的解析结果）。

### 教室归属规则

- 招生简章中 `区域` 列决定校区：`【厦港校区】报名入口` → 厦港，`【镇海校区】报名入口` → 镇海。
- 教室名前缀 `厦港教室` / `镇海教室` 会被剥离；`钢琴教室`、`大礼堂`、`礼堂02` 归镇海；`思明小学…` 归厦港。
- 单元格内换行的多教室课程（换教室/跨天）会被拆分；功能表未覆盖的教室会自动补入并标记「未登记」（当前版本功能表已覆盖简章中全部 50 间教室）。

## 自动部署（GitHub Actions）

> **当前状态**：仓库尚未配置 `NETLIFY_AUTH_TOKEN`，Actions 里的「Deploy to Netlify」步骤是 **skipped**（workflow 整体仍报 success），所以 push 不会自动刷新线上。配置下方密钥后即可恢复；在此之前需显式执行 `netlify deploy` 或走 Netlify REST API 直传，并在部署后校验线上关键标记，不能只看 Actions 是否 success。
>
> 若 `netlify deploy` 返回 `JSONHTTPError: Forbidden`，可用 CLI 同款 token 直接调 REST API：`POST /sites/{id}/deploys` → `PUT /sites/{id}/deploys/{did}`（带 `{files:{路径:sha1}}`）→ `PUT /deploys/{did}/files/{path}` 上传 required → 等 ready → `POST /sites/{id}/deploys/{did}/restore` 发布。

仓库内置 `.github/workflows/deploy.yml`，push 到 `main` 即触发部署到 Netlify 生产环境。

启用方式（二选一）：

1. **配置 Netlify Token（推荐，无需额外授权）**
   - 在 Netlify 后台 → Account settings → API tokens → Personal access tokens → New token → Generate
   - 把 token 作为仓库密钥添加：`gh secret set NETLIFY_AUTH_TOKEN --body "<token>" -R wqz93/jiugong-pingtai`
   - 之后每次 push 自动部署到 https://sng-jiugong-pingtai.netlify.app

2. **在 Netlify 后台关联本仓库**
   - Netlify → Add new site → Import an existing project → 选择 `wqz93/jiugong-pingtai`
   - 由 Netlify 自带的 CI 完成构建部署（仓库已配置 `netlify.toml`，发布目录为仓库根目录）
