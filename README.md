# 移动端培训部聚合平台

面向培训部的移动端 H5 聚合平台。当前已上线入口：**查询招生简章**（班级名称查询 / 教室查询 / 功能查询 / 空教室查询 / 晚课查询），其余入口为占位，后续陆续接入。

线上地址：https://sng-jiugong-pingtai.netlify.app

## 页面结构

```
首页（功能入口宫格）
  └─ 查询招生简章
       ├─ 导入页：导入 招生简章.xls + 教室功能.xlsx
       └─ 查询页：班级名称查询 / 教室查询 / 功能查询 / 空教室查询 / 晚课查询（双校区切换）
```

## 功能说明

| 功能 | 说明 |
|---|---|
| 班级名称查询 | 搜索招生简章「班级名称」列：输入名称中的任意字符即模糊命中（如 `舞蹈` → `少儿舞蹈` 类班级；`舞提` 这类不连续字符按原顺序出现也命中，单字亦可，英文忽略大小写），匹配字符在结果里高亮；结果按「星期 → 开始时间」排序，表格列含 班级名称 / 教室 / 上课时间 / 教师 / 剩余名额 / 学费；按当前校区过滤，另一校区有匹配时给出提示 |
| 教室查询 | 输入教室号模糊匹配（如 `409`），查看该教室功能标签与全部排课班级；表格按「星期 → 开始时间」排序，列含 班级名称 / 上课时间 / 教师 / 剩余名额 / 学费 |
| 功能查询 | 从教室功能表汇总全部功能词生成下拉（按拼音排序）；结果按教室**折叠**成表格（教室 / 功能 / 班级数 / 详情），功能列优先显示所选功能，点击教室行展开该教室全部班级（班级名称 / 上课时间 / 教师 / 剩余名额 / 学费，按「星期 → 开始时间」排序）及完整功能 |
| 空教室查询 | **点星期按钮即自动刷新列表**（与晚课查询一致，无需再点查询按钮），进入面板、切换校区时也会自动刷新；按星期输出矩阵表：行为教室（含功能），列为时段；周末 6 节（上午 2、下午 2、晚上 2），周一至周五仅晚上 2 节；「空」=空闲，「—」=已排课；**按教室号升序**（纯数字编号按数值排，`307-2` 紧跟 `307`；特殊场地按名称排在数字教室之后） |
| 晚课查询 | 周一至周日按钮，点击即展示该天**晚上 2 节**（晚1 17:20-18:50、晚2 19:00-20:30）有课的教室；折叠表格列出教室、功能、晚1/晚2 占用、晚课班级数，点击教室行展开当晚班级明细（班级名称 / 上课时间 / 教师 / 剩余名额 / 学费） |

双校区：厦港 / 镇海，可一键切换。

## 数据说明

- **不内置任何数据**。用户须在导入页选择两份文件，文件在**浏览器本地**由 SheetJS 解析，不上传服务器。
- **SheetJS 解析库 `xlsx.full.min.js` 随站点一起发布**（与 `index.html` 同目录），线上打开不请求任何外部 CDN，微信内置浏览器 / 弱网下也能正常导入，且浏览器会缓存。脚本用 `defer` 延迟加载，页面先渲染、不会出现长时间白屏。若只把 `index.html` 单独拷走，页面会自动回退到 jsdelivr CDN（此时需联网）。
- 解析结果缓存在浏览器 `localStorage`，下次打开直接生效；可在导入页底部一键清除并重新导入。
- **学费列取自招生简章的「总计」列**（= 学费 + 书杂费，含教材杂费的实际缴费总额），显示为 `¥1,000` 形式；该列为空时显示 `—`。招生简章另有「学费」「书杂费」两列，页面按需求使用「总计」。
- **班级名称查询**只读取招生简章的「班级名称」列，与教室功能表无关；匹配的是班级全名（如「【镇海】少儿舞蹈班(提高) C302」，用户口中的「少儿舞蹈提高」是简称）。匹配规则为「输入的字符按原顺序都出现在名称中」，所以连续子串、间隔字符、单个字都支持；命中字符会高亮，且对结果做了 HTML 转义，班级名含特殊字符也不会破坏页面。
- **功能关联**：以「校区 + 教室名」为键，把教室功能表的功能挂到招生简章的教室上。两表教室名走同一套规范化（剥离 `厦港教室` / `镇海教室` / `厦港` 前缀、去掉前导空格等），因此功能表的「厦港教室301」「 思明小学小操场」「镇海二楼大礼堂」都能与简章对应，不会重复统计。两个校区存在 301/302/401/402/403 等重名教室，故关联必须带校区条件。
- **功能表解析**：校区标题只识别 `厦港教室` / `镇海教室` / `镇海教室20间` 这类标题格（避免把带前缀的教室名误判成表头）；功能列按空白字符（含全角空格）、顿号、中英文逗号、分号、斜杠拆分，兼容新旧两版表格。
- 若教室功能表某校区的功能列未填写，该校区教室显示「未登记」，结果页会提示未登记数量，功能查询下拉也会给出说明。
- **晚课判定**：课程时间与晚1/晚2 任一节次重叠即计入晚课（跨节长班会同时占两节）；结果直接由班级的「上课时间」文本推导，不依赖课次缓存，因此旧版本导入过的数据也无需重新导入即可使用晚课查询。功能信息则取自导入时的教室功能表，更新过功能表需重新导入。
- **页面解析逻辑全部在 `index.html` 的内联脚本里**。`build_data.py` 是早期离线统计脚本，其中的教室功能列表为旧版快照、不参与页面运行；页面数据一律以导入的两份 Excel 为准。**功能表内容更新后，需在导入页点「清除已导入的数据，重新导入」才会生效**（浏览器缓存的是导入时的解析结果）。

### 教室归属规则

- 招生简章中 `区域` 列决定校区：`【厦港校区】报名入口` → 厦港，`【镇海校区】报名入口` → 镇海。
- 教室名前缀 `厦港教室` / `镇海教室` 会被剥离；`钢琴教室`、`大礼堂`、`礼堂02` 归镇海；`思明小学…` 归厦港。
- 单元格内换行的多教室课程（换教室/跨天）会被拆分；功能表未覆盖的教室会自动补入并标记「未登记」（当前版本功能表已覆盖简章中全部 50 间教室）。

## 目录结构

```
index.html         # 应用本体（内联样式与脚本）

```

## 本地开发与部署

```bash
# 本地预览：直接用浏览器打开 index.html（同目录保留 xlsx.full.min.js 即可离线使用）
# 部署到 Netlify（本仓库关联站点 sng-jiugong-pingtai）
netlify deploy --site 9d4db5a9-7c14-44fd-8bd0-6f18284848c7 --dir=. --prod
```

修改页面后：改 `index.html` → 提交推送 → 自动部署上线（见下）。

## 自动部署（GitHub Actions）

仓库内置 `.github/workflows/deploy.yml`，push 到 `main` 即触发部署到 Netlify 生产环境。

启用方式（二选一）：

1. **配置 Netlify Token（推荐，无需额外授权）**
   - 在 Netlify 后台 → Account settings → API tokens → Personal access tokens → New token → Generate
   - 把 token 作为仓库密钥添加：`gh secret set NETLIFY_AUTH_TOKEN --body "<token>" -R wqz93/jiugong-pingtai`
   - 之后每次 push 自动部署到 https://sng-jiugong-pingtai.netlify.app

2. **在 Netlify 后台关联本仓库**
   - Netlify → Add new site → Import an existing project → 选择 `wqz93/jiugong-pingtai`
   - 由 Netlify 自带的 CI 完成构建部署（仓库已配置 `netlify.toml`，发布目录为仓库根目录）
